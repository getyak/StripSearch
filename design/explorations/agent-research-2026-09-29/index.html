THE PROPOSAL

一个持久控制器，Search 与 Fetch 两个角色。

保留现有证据、认证与预算基础。新增统一身份服务、可加载 Skills 和 Search / Fetch 双角色长研究任务：发现覆盖平台目录，深读首批验证 X / Reddit / GitHub / 个人网站，实例数按账号与时间窗设界。

01 / RESOLVE

发现与归属

从主页和明确外链召回候选，分别记录支持与冲突。

02 / CONFIRM

只问关键差异

强依据直接展示；有歧义时用一张卡、一条辨识线索。

03 / RESEARCH

有策略地深读

跨时间选作品和表达，再追问答上下文及本人回应。

04 / UNDERSTAND

形成可修订认识

事实、自述与分析分开；保留反例、未知和撤回依赖。

01 / FIND THE RIGHT SUBJECT

输入不同，进入同一条身份链。

明确链接先建立账号锚点。用户名先找候选。邮箱只走获准的公开资料匹配；查不到时给出可行动的下一步。

用户会看到什么合成演示 · 不发送请求

呈现依据，减少判断负担

  1. 强自链支持 → 折叠预选例如：所给主页明确链接该账号。默认已勾选，可展开查看归属证据与时间。
  2. 只有相似 → 保留候选同用户名、头像、职业相似都不足以自动合并。弱候选不阻塞已明确主页的研究。
  3. 关键冲突 → 问一件事用职业、作品和辨识链接显式列出 2–3 个候选，询问最能区分的一条线索；一张卡一次提交。
  4. 用户选择 → 记录意图“是这位”不把账号简介全部升级为事实；“仅研究此账号”不声称跨平台身份已证实。
发现覆盖哪些平台，可以接什么工具？

首次发现冻结版本化 PlatformRegistry：TikHub 的 20 个文档目录平台（2026-09-29）、官方 API 与其他服务、Maigret / WhatsMyName 适用公共站点规则的并集都按目录登记，是文档目标不是已验证支持；X / Reddit / GitHub / 个人网站只是首批深读验证样本。逐平台记录发现状态：checked_no_match / candidates / needs_input / inaccessible / unsupported / deferred；超时绝不记为 checked_no_match。

工具接入位置准确边界
Exa + 外链解析先沿主页自链和作品搜索复用现有工具；相关性不等于同人
Sherlock目录内适用平台的用户名候选发现只发现存在性；不做全站无边界扫描
Maigret / WhatsMyName适用公共站点规则并入冻结目录并集去重、域名限流、缓存与错误记录；Maigret 默认 500 站点不代表全目录；命中只算候选，不做无边界递归
Gravatar Profile授权邮箱的条件性入口可能无匹配；头像命中也不保证 profile 命中
为什么不用“置信度 98%”作为自动合并依据？

模型自报分数未经校准。首版用证据规则决定 supported / disputed / proposed：强自链支持、明确冲突阻止自动合并、弱相似保留候选。以后在独立身份集上校准，再考虑概率阈值。

邮箱哈希仍是敏感标识。匿名账号不通过文风、活动时间或社交圈去关联现实身份。

02 / READ WITH A PURPOSE

历史覆盖与高价值精读，同时进行。

先枚举约定且可访问的历史索引，再分批处理每个可读正文，随后深读转折、反例和回应。X / Reddit / GitHub / 个人网站是首批深读验证样本，不是发现上限。获取顺序取决于 API，最终按时间理解；不把翻到几页称为完整历史。

有用 ≠ 热门合成材料示例
  • “新的一周，继续加油！” · 4,200 赞信息增量小，通常不精读。互动量不能证明真实性。
  • “这次发布撤回了什么、为什么” · 18 赞具体行动、决策依据、可查版本；优先阅读。
  • “回应两年前的一项判断” · 63 赞能揭示观点变化；补读原文和相反证据。

评论要读成一条对话

下面演示为什么只读 top 评论不够。全部内容为合成示例。

  1. 每个可读帖子默认先取一页首层评论，不按热度挑选；排序由供应商实际支持决定。
  2. 组合热门、最新和具体质疑；再对重要、相反或有作者回复的分支深入展开。
  3. 从本人回复索引补找遗漏路径。作者可能出现在第三层或低热度评论下。
  4. 保留父/根链、时间戳、作者 ID、角色和缺失标记；他人评价保持为评价。
覆盖、深度与停止怎样约束？

默认覆盖：每个可读正文分批处理，每个可读帖子一页首层评论；随后对重要、相反或作者回复线索深入分支与父链，默认追到深度 4、超出保留截断提示。优先读取可用字幕与原文；未读取的媒体保持 media_unread，转写/OCR 需单独授权；不递归调查评论者。

预算分总额与分批两级，每一页都扣预算，额度耗尽就停止；未做完的关键义务只能 partial。

历史试验（2026-09-29 稿试验档位，非产品上限）：每平台 6 个重点讨论、每讨论 2 页首层 + 3 条分支，以及 40/25/20/15 精读槽位，保留作排序参考，不是已验证配比。

没有读到作者回复，不等于作者没有回复；分页结束也不自动证明平台历史完整。

03 / A SMALL CORE, EXPLICIT METHODS

Tools 做动作，Skills 定义方法。

Agent 选择下一步，程序控制权限、预算和发布。把方法从单段提示词拆出来，同时让证据和状态继续由 StripSearch 持有。

新架构组件与依赖

Search 发现 → 持久控制器 → Fetch 深读（核验隔离在内）→ 人物快照

探索架构图 ↗

两个角色 + 一个持久控制器

Controller

持久程序控制器：任务图、身份政策、租约、并发、预算和快照提交。只有它能发布。

Search

发现与归属：读最小资料、检索线索、提交候选簇，关键歧义请求一次确认。

Fetch

深读与核验：枚举约定历史、分批处理正文与评论，核验隔离在内，只提交结果。

Gateway

逐请求校验能力与权限，预留预算，执行调用，保存费用和完整性回执。

两个角色，两层方法

  • 任务技能understand-person · resolve-public-identity · verify-and-synthesize
  • 平台技能research-x · research-reddit · research-github · research-website
  • 共享技能trace-conversation：根帖、问题、本人回应和上下文缺口。
  • 固定边界必需技能由控制器注入；版本与 hash 固定。技能不能扩大权限或费用额度。

工具用途关键约束
get_platform_capabilities（共享）查询平台能力注册表目录条目不是已验证支持；不支持即拒绝
discover_accounts / read_profile / search_web（Search）发现候选、读取最小资料与网络线索命中不等于归属；超时绝不记 checked_no_match

list_comments / read_thread / read_media（Fetch）评论页、对话路径与媒体保留父/根链；优先读取可用字幕与原文，未读取部分保持 media_unread，转写/OCR 需授权
read_evidence / load_skill（共享）回读证据片段、加载固定版本方法核验只用证据读取/方法加载/结果提交，不开网络发现

Search 8 个 + Fetch 10 个工具，其中 get_platform_capabilities、read_evidence、load_skill 三个共享，共 15 个不同工具。核验隔离在 Fetch 内执行，不开放网络发现。

DSH 如何演进？Pi 放在哪里？

先保留当前单步 DSH 适配器，抽出统一 ResearchRuntime。领域状态和技能注入先完成，再试验子任务内的短多步会话与真实工具调用。当前代理只准一次模型请求和 submit_decision，需要明确升级该契约。

Pi 作为可替换适配器做同题、同预算对照。不会同时引入两套持久状态；会话历史不能代替动作账本。DSH 上游 workflow 仍缺跨重启 journaling/resume 与全局 token-budget 语义。

上下文与长期记忆怎样组织？

稳定规则/技能 → 任务与身份 → 覆盖矩阵与证据索引 → 当前片段和失败记录。原文外置，通过 ID 精确回读。摘要有来源依赖，不能成为独立证据；反证、未知和版本不因压缩消失。

Person 用账号内随机稳定 ID；Account 单独记录平台 ID 与历史用户名；Claim/Evidence 内容变化创建新版本，不因过滤重新编号。身份/来源撤回沿依赖传播到报告快照。

并发和实例数怎样约束？

Search / Fetch 实例数按账号和时间窗动态设界：同一账号/时间窗内串行，跨账号可并行；每个实例只读自己的任务与原证据，避免互相引用综合结论。身份接受与发布串行；预算、取消和租约由同一控制器管理。固定 2 并发是历史设计试验配置（2026-09-29 稿试验档位），不是产品上限；调整上限需要对照实验支持。

完成的条件

  • 对象明确候选、归属、用户选择与冲突均有记录。
  • 关键问题已处理有支持、明确冲突，或经过调查的 unknown；中断导致的未做完只能 partial。
  • 证据支持且可回读引文、时间、作者、版本、权限与撤回依赖通过。
  • 研究范围真实可见覆盖率按平台、时间、正文、评论、媒体分维度记录；分母未知只报计数与范围，不用假百分比。失败与预算截断一律 partial。

如何证明 Skills 和多 Agent 值得加？

比较当前方案、单实例与多实例角色编排；再分别移除时间分层、反证采样、作者回复补路和技能方法。用冻结任务与人工 rubric 测收益。框架回放通过、供应商请求成功、人物判断正确是三个独立结论。

先做 60 个合成边界案例，再做首批深读样本（X / Reddit / GitHub / 个人网站）各 8 个资源的契约测试。20 个真实任务只能形成初步证据；需要报告分母、区间和失败，不能宣称总体零风险。
