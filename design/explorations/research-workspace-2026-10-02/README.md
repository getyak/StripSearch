# 连续研究工作区

GET-132 的交互设计验证。采用参考文件当前可见桌面布局：52 px 项目栏、200 px 导航、正文阅读区与 456 px 上下文区；以同一人物理解流程串联账号发现、一次范围确认、分批阅读、出处核查、追问与增量取证。

全部林舟 / Lantern 内容为原创合成样例。没有真实检索、模型调用、自动计费或持久化；新建研究只运行该样例。批次由“演示下一批”明确推进，没有计时器伪造进展。8 项目录不是生产全目录。静态图标导出自用户指定参考文件，没有复用参考中的真实人物照片、研究正文或整页截图。

## 运行

在仓库根目录运行 `python3 -m http.server 9296 --bind 127.0.0.1`，打开 `/design/explorations/research-workspace-2026-10-02/index.html`。无需安装应用依赖。

## 验证

安装仓库已有的固定测试依赖：`npm --prefix design/web/qa ci --no-audit --no-fund`。

运行 `NODE_PATH=design/web/qa/node_modules node design/explorations/research-workspace-2026-10-02/tests.cjs`；若运行环境不解析相对 NODE_PATH，将其指定为该目录的绝对路径。这些检查不加载任何远程资源。实际浏览器布局、原生对话框与下载另记于[验证记录](VALIDATION.md)，不能由离线结果替代。

共享设计契约与分期接入顺序见 [research-experience.md](../../../docs/research-experience.md)。`state.js` 产生唯一合成快照，界面、JSON 与 Markdown 共同使用该快照。其格式只用于设计演示，不替代生产报告或 Agent 运行契约。

## 人工验收路径

1. 新建“林舟”研究，检查全部目录与受限状态，再一次选择账号并分别授权读取。
2. 在进展中继续、暂停、停止与推进下一批；历史总量保持未知，未读原文不进入答案。
3. 对作品追问个人贡献，核对不知道的边界与来源。
4. 撤回 S2，核查依赖内容、旧回答与导出；S1 的独立账号归属依据仍保留。
5. 在窄屏打开导航与依据面板，用 Escape 关闭并核对焦点返回；没有重复输入框。
