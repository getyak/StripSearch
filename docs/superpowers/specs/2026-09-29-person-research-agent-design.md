# 人物研究 Agent：身份发现、平台深读与持续证据

日期：2026-09-29。状态：**待用户评审的架构设计稿**；不代表产品代码已变更、API 已验收或质量目标已实现。

交互阅读：[网页设计稿](../../../design/explorations/agent-research-2026-09-29/index.html)。资料核对：[研究来源](../../design/agent-research-2026-09-29/SOURCES.md)。本地基线 `cd8fee8`。

## 1. 共同理解与交付边界

用户希望只输入链接、用户名或邮箱，系统完成账号发现和归属判断；用最少操作呈现高质量消歧信号；随后按平台特点深入历史内容、代表帖子、一级评论和作者回复，形成对人的综合理解。用户已明确 TikTok 指 TikHub 类服务；首期平台为 **X、Reddit、GitHub、个人网站**。首期唯一研究意图为“了解这个人”，后续意图通过任务策略扩展。

成功以“找对对象、阅读有意义的材料、形成可复核理解、少打断且易纠错”衡量。链接数、抓取量和 Agent 数量不是成功指标。邮箱不保证可解析到人物；Reddit 可只研究公开账号，不推断其现实身份。

本轮是设计与合成交互演示，不启动真实人物研究，不采购服务，不迁移运行时。预算数字与采样配额均为实验起点。分成三个后续实施子项目：A 身份发现与确认；B 四平台内容与评论研究；C 核验、人物资料版本与评测。共享契约先行，每个子项目单独形成实施计划。

## 2. 当前体验不足的结构性原因

以下为代码推断，尚无用户任务实验支持其影响大小。

| 当前行为 | 对体验的影响 | 新设计响应 |
| --- | --- | --- |
| 无主页先搜索，再让人确认；没有成体系的跨平台归属模型 | 输入后仍像在选搜索结果 | 统一输入 → 候选簇 → 一条区分线索 |
| X 只有一页、最多 10 条本人帖子，无评论遍历 | 很难理解长期变化、讨论和修正 | 内容索引、时间分层、评论路径研究 |
| 模型轮次反复带入页面文本，最多 12 条候选 claim | 信息覆盖和上下文利用受限 | 原始材料外置，按证据 ID 取段，覆盖矩阵驱动 |
| 方法集中在单段提示词，没有版本化 Skills | 平台差异和任务经验难复用与评测 | 任务技能 + 平台技能 + 程序门禁 |
| completed 主要检查 claims 支持与页面数量 | 运行完成不等于关键研究问题已处理 | 预定义覆盖义务、已处理未知和中断缺口分开 |
| Person 主要从 run checkpoint 派生 | 人物长期积累和账号迁移能力不足 | 账号内稳定 Person、显式 IdentityLink、不可变快照 |

保留认证、账号隔离、SQLite、撤回、幂等、统一导出及现有离线路径；不重写这些已存在的能力。

## 3. 三种架构选择

| 方案 | 收益 | 成本 / 风险 | 决策 |
| --- | --- | --- | --- |
| **领域控制器 + 可替换运行时 + 有限平台 worker** | 继承已有状态/费用/撤回；按平台隔离上下文；方法可版本化 | 需要明确任务包与证据包契约 | 推荐 |
| 直接以 Pi agent-core 重建主循环 | API 边界清楚、上下文转换/工具事件可借鉴 | 迁移现有 DSH、费用代理、恢复与取消；不能凭框架名断言效果更好 | 作为同题对照适配器，收益成立再换 |
| 通用大 Agent / 全自主多 Agent + 浏览器与 shell | 探索灵活、原型快 | 并发成本、身份污染、完整性及恢复难约束 | 不作为首期默认 |

推荐先保留 DSH 运行适配器，抽出 `ResearchRuntime` 接口；以 Pi 验证替代路径。Manus 只借鉴公开的上下文工程和并行分解思想，本轮未获得其内部代码。

Pi：借鉴上下文预处理、模型消息转换、工具前后钩子和事件。DSH：借鉴 skills registry、按需加载和最小 profile。Manus：借鉴稳定上下文前缀、可回读外部记忆、保留失败记录、独立任务并行。三者都不能代替 StripSearch 的人物归属与证据规则。

## 4. 用户路径：同一页连续推进

1. **输入。** 一个框兼容 URL、用户名、邮箱；先本地识别类型，提交后才外发。URL 区分个人主页、帖子、文章、组织页；帖子需解析作者/受访者角色。邮箱默认脱敏显示。
2. **识别。** 显示“已读取你提供的主页”；主页明确且无冲突就开始阅读，同时扩展公开关联账号。不把跨平台发现全部完成设为开始研究的前置条件。
3. **最小确认。** 只有对象根本歧义或高影响的归属冲突打断。卡片最多显示 2–3 个候选，每个给一条职业/作品线索、一条辨识链接和推荐理由。提供“是这位”“都不是”“仅研究此账号”。允许补一个主页。
4. **逐步阅读。** 显示已经得到的身份依据、代表作品和有限发现；进度是“已读哪些时段、哪些平台不可读”，不显示模型思维链和伪百分比。
5. **人物页。** 快速理解 → 经历与代表作品 → 公开表达与互动 → 变化、反例与未知。引用打开原文、父帖、作者角色、日期与定位。
6. **修正与继续。** 可撤回账号/来源、修改对象、展开缺口；改对象使旧任务租约失效并清空其活动视图，晚到结果不能写入新对象。额外研究须显示增量范围和费用约束。

高支持账号自动纳入并显示理由；未解决账号折叠为“可能相关”，默认不用于人物结论。用户勾选只记录研究意图/用户声明，不修改证据支持等级。选择“仅研究此账号”会创建明确账号范围，不宣称它已与其他账号证实为同一人。

确认问题按“能区分多少候选、会影响多少下游研究、用户回答负担”排序；初次最多问一个最有区分力的问题，例如“是 Atlas 的作者，还是摄影作者？”不要求用户评审全部账号。后续只有新增关键冲突才再次打断。界面提交反馈目标 <200ms，首个有证据片段目标 30–60 秒；二者是待测体验目标，不是供应商 SLA。

## 5. 身份服务：发现和归属分开

### 输入与候选召回

统一 `InputEnvelope`：`inputId, kind, normalizedValue, anchors, intendedScope, ownerId, authorizationRef?, inputRevision`。邮箱原文不进入普通日志/报告；哈希仍作为敏感标识管理，不宣称匿名。

发现顺序：已知主页 → 主页明确外链/公开职业主页 → 按姓名与作品的定向搜索 → 四平台用户名候选。首期不跑无边界全站扫描。候选发现仅读取归属所需的最小资料，深度帖子与评论研究只针对被允许的账号范围。

| 候选工具 | 价值 | 使用决定 |
| --- | --- | --- |
| Exa + 主页链接解析 | 从已有锚点沿明确线索扩展 | 首选，复用现有工具 |
| Sherlock | 指定用户名存在性发现 | 可选受限适配器；只在允许平台探测，不将命中当归属 |
| Maigret | 更丰富的用户名发现/解析 | 留作对照；首期不启用其广泛或递归采集 |
| Gravatar Profile | 通过已获授权的邮箱哈希获取公开资料与关联账号 | 条件性邮箱入口；命中率与可用范围待实测；404 不表示没有社交账号 |

邮箱不自动去掉 `+tag`、点号或猜测用户名；仅按目标服务规范处理。没有授权或可用匹配来源时，说明限制并请用户补公开主页。第三方人物 enrichment 返回的是候选与来源线索，需要单独验证，不购买“身份真值”。

### 归属证据政策

`IdentityLink` 保存证据、反证、来源组、有效时间、policyVersion 与状态 `proposed / supported / disputed / rejected / revoked`。另存 `userSelection`，不与 supported 混同。

- 平台稳定 ID 证明该平台账号连续性，不证明跨平台同人。
- 由已确认锚点发出的明确本人账号链接，可支持归属；检查是否是团队账号、访谈对象、引用或被入侵/迁移的旧链接。
- 双向明确互链、公开验证的账号关联，可增加支持；两个页面复制同一介绍不算两份独立证据。
- 姓名、头像、相同用户名、相似职业只产生候选。涉及匿名账号时不以文风、活动时间或社交圈猜测现实身份。
- 存在关键反证时停止自动合并；不能用几个弱相似分抵消冲突。
- 无明确链接但有独立职业证据的候选，首版进入 review；在冻结身份集上校准后，才考虑扩展自动接受规则。

先用可解释的证据等级和接受政策，不展示 LLM 自报的“98%”。未来概率须按平台和线索类型校准；评测需同时报告错误合并、错误拆分与候选召回率。

## 6. 平台研究：先建索引，再选择精读

默认问题矩阵：经历/作品贡献/公开观点/互动方式/观点变化/反证与缺口。根据对象资料标记适用项，不能读完之后为了得分删除未覆盖项。每个问题记录 `unseen / evidence_found / conflicting / resolved_unknown / blocked`，并指向证据和后续动作。

### 时间与内容采样

抓取顺序由 API 决定；呈现和分析按时间组织。不能承诺所有平台支持“最早一页”或完整历史。若只提供从新到旧的游标，就逐页建立索引并记录最早已到时间；时间搜索和旧文链接只补洞，不当作连续历史覆盖。

每页先去重、识别转发/模板/广告、提取日期与内容类型，再选择全文精读。尽量覆盖多个时期、主题和内容形式。初始精读槽位可分配为：40% 代表事件/作品、25% 时间覆盖、20% 反例/修正、15% 低热度探索；小样本按可用性调整，并记录跳过原因。这些是待实验配额，不是研究规律。

排序使用多轴可解释特征：问题相关性、具体行动/细节、信息新颖度、可核查程度、变化/冲突价值、上下文完整性。互动量仅为同平台、同账号、相近发布时间的曝光代理，不能当真实性或唯一质量指标。重复转述折扣；缺点赞字段不扣证据分。第一阶段可以用明确规则 + 小批量 LLM 分类，不先训练黑箱总分。

用户可以另选“尽量读完可访问历史”：先展示可估计的页量、额外预算与时间范围，再按游标推进；断点允许后续继续。只有接口明确表示结束且无已知缺口时，才称“该接口可访问范围已读完”，仍不能称账号完整历史。默认综合了解先交付分层样本，避免把长时间无结果的等待作为深度感。

### 四个平台的方法

| 平台 | 核心材料 | 独特策略 | 明确限制 |
| --- | --- | --- | --- |
| X | 本人帖子、长串、引用外层文字、回复 | 账号时间线 + 主题检索；完整 thread；针对作者回应补上下文 | TikHub 文档有评论/最新评论/本人回复端点；完整树、排序语义和历史深度仍需逐端点试验 |
| Reddit | 本人 submitted 与 comments、社区上下文、嵌套讨论 | 先读本人评论索引，再回到所在帖子；保留 subreddit、parent_id、编辑/删除状态 | 走获准的数据访问路线；Devvit 文档不是任意外部服务的权限证明；不恢复删除内容 |
| GitHub | 原创项目、PR、review、issue、release | 围绕具体作品追贡献和维护；读问题—修改—合并—后续 | 仓库归属、star、职位不能证明个人贡献；API 分页边界单列 |
| 个人网站 | about、文章、作品、RSS、允许的 sitemap | 先身份外链，再按时间与主题读代表原文；Exa 不足时 Firecrawl | 自述仍是自述；页面版本、日期不明与采集时间分开 |

Reddit 是首期设计范围；若未取得可用数据接入，则明确为 blocked，不悄悄以搜索摘要代替帖子/评论深读。

## 7. 评论研究：以对话路径为单位

“一级 → 二级”是读取策略，不是跨平台通用事实。统一模型使用 `rootId, parentId, authorAccountId, depth?, createdAt, ordering, retrievedAt, accessState`，保留原生关系；只有树结构得到证实时才写 depth。

1. 选定有研究价值的帖子，读取根帖与可见的首层讨论。
2. 若端点支持，组合 top 与 new；若只有未知推荐排序，保存 `ordering=provider_default`，不能标为 top。低排序但有事实、质疑、修正或作者回应的评论也进入样本。
3. 先判断评论是否增加上下文、事实线索或提出可回答问题；表情、泛赞和重复争吵降低优先级。
4. 对选中评论展开子回复，同时用本人回复/评论索引寻找作者参与路径，避免只能在热门一级评论下找作者。
5. 取回作者回复的祖先链。作者回复不保证在第二层；默认追踪到深度 4，超过时保留截断提示，可在预算内选择性扩展。根帖→问题→本人回答是一份对话证据包。
6. 核对作者 ID，区分本人、第三方、引用原文与无法确认；作者回答证明其表达，不自动证明事实。
7. 记录请求排序、游标、已读数量、缺失父节点、删除/隐藏节点、下一页。没有看到回复只能说明已读范围未见。

初始每平台最多 6 个重点讨论，每讨论最多 2 页首层和 3 条选中分支；每次分页消耗同一网络预算，额度耗尽就停止。不得递归建立其他评论者的人物档案。

## 8. Tools、Skills、Policy、Agent 的接口

Tool 取得/存取资料；Skill 指导如何研究；Policy 强制权限、预算与发布约束；Agent 在允许范围内选择下一步。四者分别版本化。

### 拟定工具契约（均为设计名，不是已存在 API）

| 模型工具 | 输入重点 | 返回 / 限制 |
| --- | --- | --- |
| `search_public` | query、平台、允许时间范围 | 候选、原 URL、限制；每次一个适配器请求 |
| `resolve_account` | URL / 允许的 identifierRef | 账号 ID、资料、链接、页面角色；不返回“真实身份已证明” |
| `read_document` | sourceRef、locator? | 一份原文或证据片段及版本；HTML 补读有独立计费动作 |
| `list_activity` | accountId、kind、cursor、sort? | 一页 posts/comments/PRs 等、原生游标与覆盖元数据 |
| `read_item` | platform、itemId | 根帖/PR/文章详情、作者与上下文链接 |
| `list_replies` | itemId、cursor、sort? | 一页回复/评论；不隐藏子分页 |
| `expand_context` | parentRef / branchRef | 一次取父上下文或缺失分支；失败保留 gap |
| `load_skill` | skillId、固定 version | 经审核的方法正文与依赖引用；无任意路径执行 |
| `read_evidence` | evidenceIds、locators | 同账号、未撤回的证据片段 |
| `submit_evidence` | statements、引用、归属、反证、coverageDelta | 候选证据包；不直接成为报告事实 |
| `propose_next` | gap、action、expectedGain、stopReason? | 控制器审核下一任务/停止建议，不授予子 Agent 自由启动权 |

平台仅公开 capability registry 确认可用的操作。一个模型工具如果对应多个底层 HTTP 请求，必须先展开为独立动作逐个预留和记录；不得通过工具封装隐藏成本。读本地证据/加载技能不消耗供应商请求数，但计入步骤与上下文 token。拒绝不支持的 sort/date/depth，不伪装成功。

内部确定性服务负责 `normalize_input`、候选去重、IdentityLink 决策、任务派发、预算结算、覆盖检查与 snapshot 发布；不全部暴露为模型自由写接口。

### 初始技能目录（方法草案）

| Skill | 触发 | 必交产物 |
| --- | --- | --- |
| `understand-person` | 默认研究目标 | 适用问题矩阵、阅读计划与认识边界 |
| `resolve-public-identity` | 多账号归属 | 支持/反证链及候选簇；不得自己合并 |
| `research-x` | 已允许 X 账号 | 时间覆盖、thread、本人回应与缺口 |
| `research-reddit` | 已允许 Reddit 账号 | 提交与评论覆盖、父链、社区上下文 |
| `research-github` | 已允许 GitHub 账号 | 个人贡献链、维护与协作记录 |
| `research-website` | 个人网站 | 原作索引、时间版本、自述及外链 |
| `trace-conversation` | 重点讨论 | 根帖、问题、作者回应、截断范围 |
| `verify-and-synthesize` | 待发布证据包 | 原子断言核验、反证、替代解释、缺口 |

目录只提供简短说明，按阶段加载任务技能和相应平台技能。mandatory 技能由控制器注入并验证产物，不能仅指望模型自主记得加载。每次运行固定 `skillId/version/hash`，中途不热更新。Skill 不修改工具 allowlist、预算或身份政策，不加载用户机器的全局 skills，也不把网页内容当新技能。扩展脚本若确有必要，单独代码审查并在受限执行器运行。

## 9. Runtime 与持久调度

`ResearchRuntime.run(taskPacket, toolGateway, modelGateway, signal) → events + evidencePacket`。TaskPacket 包括账号范围、固定问题、能力清单、技能版本、证据引用、预算子额度、parentRun/attempt/identityRevision。

初期保留当前单步 DSH 适配；先实现领域状态/技能注入。之后评估每个子任务内的短多步 DSH 会话，开放上述真实工具；每轮通过网关扣账，阶段完成提交证据包。这个变化需要修改当前“只允许 submit_decision、只准一次模型请求”的代理契约，不能仅新增几个工具注册就视为完成。

单 Supervisor 管理任务图；同一种 worker 通过 Skills 专门化，初始全局每研究最多 2 个 worker 并发，不递归派生。只有账号范围确定后才并行 X/Reddit/GitHub/Web；身份判断和最终发布由单一协调者串行提交。平台 worker 不读取其他 worker 的综合结论；Verifier 读取原始证据和 claim，避免相互认可变成真值。

SQLite 起步新增 `research_tasks`、lease/attempt、`research_actions` 和 outbox。状态 `queued → leased → running → succeeded | partial | blocked | failed | cancelled`；用户根任务仍可 needs_input。租约过期后的新 attempt 使用 fencing token，旧 attempt 无权发布。可安全重放的本地计算与费用未知请求分开处理；后者先对账或明确停止，不能跨 provider 承诺 exactly-once。

所有模型请求含规划、提取、核验、压缩和重试都进入 modelGateway。候选已取消/版本过期时拒绝新动作；晚回包可结算已有费用，不能改动发布状态。

## 10. 上下文、数据与撤回

上下文四层：稳定规则与固定技能 → 任务/身份范围 → coverage 与已核验事实索引 → 本轮证据片段/动作失败。正文保存在按权限分区的证据库，模型通过引用读取。摘要保存依赖 ID，不成为独立来源。压缩不能丢掉反证、未知、来源定位或访问限制。

持久数据最小实体：Person（账号内随机 ID）、Account（稳定平台 ID 可空）、IdentityLink、SourceRevision、Evidence、Claim、Event、ConversationPath、CoverageSlot、ResearchRun/Task/Action、ReportSnapshot。Claim/Evidence 使用稳定 ID，内容变化产生 revision，不能因过滤后重新编号而改变引用含义。

依赖：`IdentityLink / SourceRevision → Evidence → Claim → Event / Analysis → ReportSnapshot`。引用边区分支持/反证；保存原始来源组，转载不增加独立性。发生撤回时：使依赖失效 → 中止相关 worker 租约 → 推进 personRevision → 重算仍有独立支持的结论 → 生成修订快照。已下载文件无法召回，导出带截至时间与 revision。

ReportSnapshot 只有确定性提交服务可发布：身份允许、引用与内容版本有效、权限正确、核验结果完备、coverage 义务已处理。Web/JSON/Markdown/HTML/PDF 从同一快照派生。跨账号不共享人物私有推断；本地授权材料和公开来源仍按最严格依赖限制导出。

## 11. 预算、停止与失败体验

初始离线/小规模试验配置：最多 80 次供应商请求、24 次模型请求、300k 输入 / 32k 输出 token、8 分钟、2 个 worker。预留 20% 模型/时间额度用于核验与综合。它们是待验证上限，不是用户等待时长承诺，也不是建议直接替换现有线上配置。

阶段参考：身份发现 8 次网络调用、内容索引 32、选择精读/评论 32、恢复余量 8。阶段可由协调者转移未用额度，不能动用保留的核验额度；闲置额度不要求花完。已知上界才承诺金额上限，未知费用显式记录。单位成本计算包括失败、partial、取消、重试与核验。

停止规则：关键适用问题均有支持、冲突说明或已充分调查的 unknown；时间与来源多样性检查通过；两轮无新增独立有用证据。访问失败/预算截断造成未做完的关键义务只能 partial；unknown 不等于 partial，也不能通过缩小 rubric 把 partial 改 completed。

| 失败 | 后台 | 用户看到 |
| --- | --- | --- |
| 一个平台 429/不可访问 | 停该分支，记录游标和 retry-after；其他平台继续 | “Reddit 本轮未能读取，其他资料已保留” |
| 历史未翻到底 | coverage 标 capped，不写全量 | 最早已读时间、时段缺口 |
| 作者回复缺父评论 | 保留缺失标识，相关解释降级 | “回复上下文不完整” |
| 身份冲突 | 暂停受影响账号，继续无争议锚点 | 一张具体差异卡 |
| 模型无效结构/引用 | 最多一次预算内修复，仍失败降为摘录 | 部分发现与不能下的结论 |
| 付费结果未知/重启 | 冻结动作，等待对账；不盲重试 | 明确中断与已有结果 |

## 12. 评测与迁移顺序

先冻结 60 个合成契约/对抗案例：链接角色与输入 10、身份错合并/拆分 15、历史与评论树 15、撤回/隔离/注入 10、预算/恢复/取消 10。通过只证明程序行为，不作为人物质量 benchmark。

再进行获准材料的 provider 契约试验：四平台各 8 个已知资源（共 32），覆盖分页、父链、作者 ID、删除、空响应、截断与收费。每个端点单独标记 `documented / contract-tested / live-verified`，不能平台整体打勾。

最后冻结 20 个获授权人物任务：当前方案、增强单 worker、增强最多两 worker；同预算比较，先用探索样本找故障，再冻结回归与留出实体组。人工冻结关键问题、身份关系、可接受 unknown 与禁止断言；保留失败与成本。无独立人工评审就标探索，不称 gold。

发布门禁：严重错人/伪证/越权的已知回归零未解决；引用 ID、版本和撤回传播确定性通过；覆盖不低于同预算基线；同时报告身份 precision/recall、作者回复找回率、关键断言支持、核查时间、首个有价值结果 p50/p95、总成本/合格任务。百分比目标必须带样本量和区间。

消融优先：去掉时间分层、只读热门、取消作者回复补路、关闭反证采样、无技能与有技能、单 worker 与两 worker。它们分别验证用户关心的体验是否由新增机制带来。

| 批次 | 可评审交付 | 放行条件 |
| --- | --- | --- |
| A 身份 | 统一输入、Account/IdentityLink、最小确认卡、四平台候选 | 明确主页无重复确认；同名不误合并；邮箱失败有清楚下一步 |
| B 平台深读 | 能力注册、分页、时间覆盖、评论路径、技能版本 | 32 资源契约验证；完整性诚实；作者归属与评论上下文回放通过 |
| C 研究闭环 | 覆盖驱动调度、证据包、稳定对象、撤回、短会话 | 重启/取消/费用未知/跨任务撤回；同快照导出 |
| D 质量取舍 | 20 任务配对与消融，DSH/Pi 可选对照 | 人工核查成本与覆盖改善有证据；否则缩减复杂度 |

代码落点：将现有 `controller.ts` 中身份、规划、取证、核验职责拆为领域服务；沿用 `research-store.ts` 账本扩任务租约；将 `tool-contracts.ts` 扩为 capability/page/receipt 契约；`planner.ts` 变上下文构建和运行时适配；`types.ts`、canonical 先升级，再修改 UI 与导出。feature flag 保留旧路径和旧报告读取。
