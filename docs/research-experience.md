## 一条连续路径

1. 输入一个公开主页、明确用户名或姓名；默认目标是“了解这个人”，用途和时间为可选补充。授权邮箱需单独说明使用范围；不猜用户名、不从姓名生成规则探测操作数。
2. 先展示锚点和适用平台的真实检查状态。有清楚公开锚点时可阅读已允许账号，同时发现其他账号；身份歧义只问最有区分力的一问。
3. 一次复核账号研究选择与范围：哪些账号有归属依据，哪些只是用户指定，时间/正文/媒体/评论深度与总额/批次预算。支持“仅研究这个公开账号”；用户选择不升级身份支持等级。
4. 边读边展示已核验片段与缺口。保持同一个人物工作区，平台可以失败，已核查内容仍可读。控制器保存游标、动作与范围版本。
5. 摘要、事件、作品、表达与互动均能回到材料；从结论发起追问时携带该结论及证据引用。扩大范围或新付费读取先展示增量计划，再提交新的范围版本。

输入、明确点击提交之前不外发。没有真实连接时保留输入并说明能力缺口；演示不能对任意输入返回一份伪装的人物报告。

## Search 要深入到哪里

“深”分为发现深度与理解深度。前者是账号路线、排除与缺口，后者是时间连续性、作品贡献、原始内容、作者回应与相反证据；都不以更多链接或更长文字替代。

| 层 | 动作 | 必须留下的证据 | 停止/降级 |
| --- | --- | --- | --- |
| 输入角色 | 区分主页、帖子作者、被采访者、组织与项目账号 | 接受的输入类型、角色与解析回执 | 角色不明时补一个区分线索，不把组织当个人 |
| 锚点扩展 | 读取已允许主页的明确自链，解析目标角色 | 原 URL、来源修订、链接位置与指向 | 第三方链接只算候选，团队或迁移链接保留限制 |
| 全目录召回 | 冻结目录版本，按自链/明确用户名规则/平台搜人/官方/允许站点搜索规划 | 每平台路线、输入操作数、请求键、返回状态 | 缺 handler/key/授权为具体缺口；失败绝不写成无账号 |
| 去重与归属 | 按平台命名空间 + 稳定 ID 去重；保留来源独立组和冲突 | IdentityLink 支持、反证、policyVersion；用户选择另存 | 同名/头像/文风只生成候选；硬冲突阻断同人发布 |
| 价值排序 | 按区分力、作品原作、历史跨度、独立性和现有问题缺口排序 | 推荐理由和下一条有价值动作 | 排序不会改变归属、权限或完整性义务；不按热度丢正文 |
| 发现回流 | Fetch 发现新公开账号线索后交回 Search | 新线索的来源、范围版本、来源角色 | 未确认/未授权账号只入候选，不能偷偷扩范围 |

每个平台显示一个可追溯当前状态：候选、检查无匹配、需补充、不可访问、不支持、待处理。多条路线可有不同回执：一路受限但另一路成功不能平台整体报失败；已有外链但正文未读不能计正文覆盖。目录分母已知可显示“已检查 N / M 项”，明确这是目录义务，不是账号数或准确率；未知历史分母仅显示计数、时间边界和游标。

关键确认卡展示：公开账号、可区分的作品/职业线索、一条支持、一条冲突/限制、推荐原因。操作为“研究此账号”“不是此人”“暂不采用”；用户选择的账号可以作为独立账号研究，不强行连接到其他账号。恢复被排除候选不会自动恢复已撤回证据。

## Fetch 的问题与阅读账本

默认覆盖六项：经历、作品与个人贡献、公开观点、表达与互动、变化/修正、反例与未知。问题在开始前标明适用性，不事后删除未解难题。UI 由现有 CompletionScopeSpec / Observation / Assessment 派生；不能从报告字数或 provider 成功响应推导完成。

不适用需冻结理由；权限、能力或预算不足均属受阻，不算已调查未知。

| 维度 | 用户看到 | 实现约束 |
| --- | --- | --- |
| 历史 | 最早/最晚已到时间、游标、连续窗口与未读洞 | 从 API 实际排序分页；搜索旧文不能证明中间全部读完 |
| 正文 | 已枚举、已读、未读、跳过理由、不可访问 | 约定范围内每个可读正文分批处理，优先级只改变顺序 |
| 媒体 | 文本替代、字幕/转写/OCR 状态与限制 | 无媒体能力时不把正文读完计为媒体完成 |
| 评论 | 首层覆盖、根帖、关键问题、本人回应、缺父链 | 默认每帖一页首层评论；深分支依约定且保留上下文 |
| 问题 | 有证据、冲突、已调查但未知、未处理、受阻 | unknown 需要调查回执；预算耗尽保持 partial |
| 费用 | 读取/模型调用、已知估计、未确认费用、增量范围 | 总额与批次两级；未知计费请求先对账，不能盲重放 |

读取优先：原作/原公告 → 个人贡献与后续维护 → 时间缺口 → 修正与反例 → 相关讨论与本人回应。引用聚类同源转载；不把十篇转述计作十份独立支持。每个结论保留“能说明 / 不能说明 / 反证与替代解释”。

## 人物工作区的内容与动作

左列是同一人物的摘要、账号、研究进展、覆盖与范围、作品、时间线、公开互动。主阅读区回答问题；侧区在对话、账号依据、引用之间切换。固定项目栏只留状态、继续/暂停及导出，更多动作放在菜单。手机保留同一信息顺序与操作，dialog 原生焦点约束、Esc 和关闭返回触发控件。

结论保留四种独立标签：本人自述、来源页面表述、原文支持的事实、分析推断；不必分成四个页面。不能从项目归属推断个人贡献或从一次互动推断私交。材料有来源 ID、修订、作者角色、发生时间与材料时间、短摘录、定位、依赖。

追问先选择范围：“仅当前已读材料”或“继续取证”。前者无新增检索；缺证据直接说明。后者显示问题、账号、时间、动作与预算，不把局部追问混为整体研究完成。原型只支持明确列出的预设追问，其他自由输入返回“演示未连接模型”，不会编造回答。

撤回先显示影响：账号归属、结论、时间线、互动、导出。提交后保留稳定引用 ID，使依赖失效并中止受影响任务；有剩余独立支持的条目仍按政策重评。恢复来源保留修订轨迹。已下载文件无法召回，快照显示截至时间、scopeVersion、revision 和 provisional/partial。

## 合成设计演示合同

[工作区演示](../design/explorations/research-workspace-2026-10-02/index.html)是独立本地呈现，不替换 Web alpha。共享合成状态先定义，再渲染所有视图和导出。演示引用 S1 About、S2 README、S3 讨论、S4 无法访问旧日志；只授权网站与 GitHub 默认阅读。同名 GitHub、X 候选保持独立；选择不升级支持；新增范围版本后不得带入上版的未保存选择。所有材料复用 [原合成语料](../design/web/NEXT-DESIGN.md)的边界，不抓取 fixture URL。

使用 8 项演示目录，显式标注不是生产全目录；默认含候选、无匹配、受限、不支持、待处理示例。状态推进由用户动作触发，不用计时器伪造后台研究。暂停、停止、恢复保留范围与选择；正文与评论覆盖不同步伪完成。报告和 JSON/Markdown 来自一份快照，撤回后的旧结论不继续显示为可靠。刷新重置为合成默认状态，不保存用户输入、邮箱或真实研究资料。

## 验收与发布判断

- 程序：同名不合并；选择不提升支持；权限与范围分离；晚包失效；取消/重启/预算未知可恢复；撤回与所有导出一致。使用现有离线测试，禁止真实网络与付费 API。
- 体验：首次输入到首个可核查发现的 p50/p95、需要用户确认的次数、回到原文核查所需动作、窄屏/键盘/减少动态、停止后续读是否明确。目标需实测，当前不报告达成数值。
- 研究：账号召回与误合并、按时间/来源独立组覆盖、个人贡献支持、作者回应与父链找回、严重错人/伪证、核查时间与全部成本；记录样本、失败、partial 和人工裁决。
- 放行：最新提交所有适用 CI 和仓库门禁通过；独立 review 的 P0/P1 关闭；端点 live 验收后才启用。若深度成本增加但理解与核查无收益，缩减调度复杂度。

当前已完成的是设计与合成演示；生产长研究接入、端点 live 验证、人物质量评估与上线验收分别交付。
