# Fetch 平台方法与验证顺序

2026-10-07：本页是接线与端点试验计划。公开文档核对不代表真实端点可用、完整历史覆盖或研究质量验收；合成回放不提升任何平台的 `live_verified` 状态。覆盖回执以 [GET-95](fetch-coverage.md) 为准，完成判定以 [GET-60](research-completion-domain.md) 为准。

## 同一条执行链路

```mermaid
flowchart LR
  S[已确认账号与冻结范围] --> L[分页枚举与原生游标]
  L --> B[每条可读正文]
  B --> C[默认评论首层一页]
  C --> T[重要对话与作者回复分支]
  T --> M[媒体文本或明确缺口]
  M --> P[带证据依赖的 pending findings]
  P --> V[只回读已有证据的核验]
  V --> A[确定性完成评估]
  A --> R[继续未处理义务或保留缺口]
```

程序控制器负责权限、分页、动作记录、检查点、结算与完成规则；模型负责研究优先级和解释。优先级改变读取顺序，不能静默删除低互动正文。每次网络动作前记录 intent；结果未知时停止自动重放。来源正文是数据，不能改变账号范围、工具权限或发布状态。

## 各平台读取方法

| 平台 | 建议读取路线 | 应保存的上下文 | 端点试验重点 |
| --- | --- | --- | --- |
| X | 已确认账号的帖子与本人回复分别分页；详情补正文；帖子评论读首层；沿重要、作者回复或反证分支回读父链 | 原生账号/帖子 ID、原帖与引用帖区分、conversation/父节点关系、实际排序、分页边界 | 长正文、本人回复遗漏、引用与转发归属、删除父帖、重复/循环游标、评论排序差异 |
| Reddit | 本人 submitted 与 comments 分开枚举；评论回到根帖与父节点；选定分支继续展开 | subreddit、根帖、父评论、原生 permalink、未展开节点与作者角色 | `after` 与子评论 cursor 分开保存；向下 replies 不能证明祖先完整；两条 provider 路线独立验证 |
| GitHub | 账号发现公开仓库及贡献线索；沿具体 PR、issue、review、commit 与 release 读取原始对象 | 仓库、对象 ID、commit SHA、作者/审阅者/合并者的不同角色、讨论与实际变更 | 不能以 profile 或近期 events 代替全部贡献；PR 创建不等于合并或成果；关闭/撤销对象重新评估 |
| 个人网站 | 已知 URL 先读取正文；正文缺失才补抓取；沿站内作品、归档、分页与显式链接枚举 | canonical URL、原始与重定向 URL、发布日期的不确定性、完整捕获文本与 hash、目录/正文分别计数 | 搜索摘要不能算正文；导航/列表不是文章；JS 页面、附件、付费/登录边界与截断必须明确 |

以上是设计方法，尚未新增真实适配器。X 的 TikHub 官方页面列出帖子、本人回复及帖子评论端点，具体响应解析、分页与费用仍需试验。[TikHub X 文档](https://tikhub.io/twitter-api)

Reddit 的两条候选路线、配置缺项和逐端点验收沿用 [Reddit 路线契约](platforms/reddit-routes.md)。不能把匿名入口失败推导成所有 provider 路线不可用。

GitHub 官方 events 文档当前限定最多 300 个、最近 30 天的事件，因此用它发现近期线索时应记录窗口限制，再回到具体对象。此限制属于该 API，不能变成 StripSearch 的累计研究上限。[GitHub events](https://docs.github.com/en/rest/activity/events)

网站读取可沿用 Exa Contents，缺正文再考虑 Firecrawl Scrape；返回 text/highlights/summary 的用途分别登记，单次提取成功不证明全文完整。[Exa Contents](https://exa.ai/docs/reference/get-contents) · [Firecrawl Scrape](https://docs.firecrawl.dev/features/scrape)

## 接入器的完成凭据

每个底层请求保存 provider/版本、输入指纹、请求 ID、原生身份、获取时间、实际排序、下一页游标、访问边界、截断/缺口和已知或未知费用。预注册的来源 pin 必须匹配返回的账号、item/source ID、revision 和完整捕获文本 hash；hash 只证明记录一致性，不证明陈述真实。

`cursor=null`、空页、模型 yield 或成功 HTTP 状态都不能单独证明读完。只有经验证的端点终止协议、无未解释游标与已知缺口，才可以确认该接口在本轮约定范围内耗尽。第三方陈述保留原作者，不能改写成研究对象的自述。

## 从离线到真实试验

1. 使用合成语料和真实 SQLite 验证跨批次、关闭重开、重复页、游标循环、失败、撤销、范围变更、来源错绑及未知动作结算；含 `save_findings` / `read_evidence` 分块暂存与核验回读（>100 同账号条目/依赖、>50 findings）的中断/重开续跑，无遗漏、无重复成功调用；所有已确认 P0/P1 修复并独立复核。
2. 按平台选择公开且获准的样本，固定账号与时间窗，用真实 adapter 连续读取至少两页及一条含父链的对话；逐项记录响应字段、限制、实际请求与费用。
3. 对每项能力分别升级状态，再运行具有人工标注的研究评估；请求成功率、覆盖率与分析质量分别报告。

真实试验需要运营配置的服务凭据、获准样本 URL/账号、研究问题与时间窗，以及本轮调用/费用授权。凭据通过本地或部署配置读取，不进入聊天、Git、fixture 或 CI；原始研究材料只保存到授权的私有目录。没有这些验收输入时继续离线验证，保留真实端点与效果验收未完成。

研究默认无固定累计内容/请求上限。测试批次可以有调度量子和本轮费用范围，耗尽后保留可恢复状态，不能因此宣布研究完成。本次不执行部署。
