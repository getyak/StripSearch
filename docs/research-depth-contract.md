# 有界研究的深度契约

状态：本轮实现。此契约修复现有 Web alpha 的采集与完成判断，不冒充尚未接线的 GET-59 Search/Fetch 长研究运行时。

从用户名开始，搜索原始主页并请用户确认对象；继续沿真实自链发现别名账号、作品、原作索引和历史。用户名相同只生成候选；机构仓库不等于个人贡献。来源文字和 machine-readable 文件均是不可信材料，其中的 Agent 指令不能改变权限或研究方法。

## Search → Fetch → 核验 → 可继续的报告

1. Search 返回发现材料；搜索摘要可引导阅读，但不当作已读正文。Fetch 按原 URL 阅读，保存作者、发表/获取时间、读取方式、截断和可见自链。相对链接以来源页解析；链接发现先于正文截断。Exa 提取的 `extras.links` 可补足丢失的页面导航，仍须经过公开 HTTPS 校验。
2. 规划必须围绕经历变化、具体作品与个人贡献、原作观点、互动回应、反证与限制安排检索和深读。优先原始作品、不同时间的记录和具体讨论；个人主页、身份文件、时间线和翻译属于自述/同来源族，不是多个独立证明。
3. 用有界批次读取已发现的多个 URL，每个动作仍独立预留/结算一个供应商请求。局部已知失败保留缺口并继续其他分支；未知扣费和未结算动作禁止盲重试。保留独立核验预算。
4. 确定性完成条件不再是“两页 + 一条通过的断言”。报告分别展示各研究问题的已支持材料与缺口；不能靠模型说完成、主页数量或检索空结果认定全研究完成。断言只使用已读取的原文，核验与身份仍分开。
5. 总请求/token/时间上限保持原默认值；部署可明确配置更长批次，回执展示实际冻结限制。预算不足返回 partial，follow-up 延续有效原文与未读线索，撤回后不复用其派生结果。

## 验证边界

离线合成测试覆盖相对/机器文件/页面自链、尾部链接不被截断丢失、拒绝内部地址、搜索摘要不冒充原文、分支失败与批次核验保留、完成判断、重启和撤回。公开真实人物的原始材料与研究回执只在授权私有工作区保存。真人测试是探索验收，不是人工质量 benchmark。

接口依据：[Exa Contents](https://exa.ai/docs/reference/get-contents) 与 [Exa Search](https://exa.ai/docs/reference/search)。`extras.links` 是提取出的出站链接，不能证明账号同人，也不代表全站历史。广泛平台注册表扫描、完整社交分页/评论/媒体、两角色工具网关、持久跨批总预算和租约仍按已有 Linear 任务分别验收；此增量不能据此关闭它们。

## 本轮实现边界

已选范围的 Fetch 保留实际观察到的 HTTPS 页面与出链地址，包括尾斜杠、大小写及查询参数；仅移除不参与 HTTP 请求的 fragment。不把旧 anchor/allowlist 的归一化规则用于改写具体文章地址，也不据此宣称 URL 等价或重试失败地址。派发仍须通过已发现地址、当前范围及撤回守卫，原始回执与正文不改写。

新范围核验将每条候选引文的归因依据由服务端绑定为 `quote_first_person`、`native_authored_post` 或 `page_text`：第一人称只是候选语义检查条件，不会自动支持；原生帖子须绑定读取回执中的 native ID 与作者 handle；主页第三人称简介、出版物归属和账号目录仅是页面陈述，不能改写为本人自述、创办或个人贡献。模型不得提供或更改此标记。新核验使用不同 action key 与请求合同，旧已结算核验结果不作为新归因核验回执；历史未标记记录不被重标。

新标记陈述不使用依赖列表顺序的“同文/上文”代指；每条需在独立展示、分组和导出后仍自包含。约数不能被增加为“超过/至少/两年多”。这些确定性守卫只检查有限明显反例，不构成通用语义证明；每条仍需独立语义核验和实际原文检查。账号偏好或博客归属不能填充带时间经历、作品个人行动维度；“想像某人一样”不能改成实际成为该人。

逐条独立核验拒绝后，已选范围允许最多两轮提炼修正，且必须在本次冻结模型/token/时间预算内保留再次核验的额度。反馈保留候选陈述、原始引文和拒绝原因，仅供改写，不作为证据。已经通过的陈述保留；新陈述仍需自己的实际原文引文与新核验回执。连续失败、额度不足、取消或撤回则停止为 partial，不降级为自动支持，也不把逐字摘录冒充综合事实。旧非范围研究保持历史终止行为。

旧 alpha 接收最多四个独立动作的 batch；每个动作仍单独计量并校验已发现 URL。五类问题的证据可用性从通过独立核验且由读取动作获取的断言计算，撤回后重新计算；它不是覆盖百分比。未填维度的历史报告仍可读，但不能满足新的完成条件。JSON、Markdown、HTML/PDF 与界面使用同一 canonical 问题状态。

新配置可显式增加单批限制：`STRIPSEARCH_RESEARCH_TOOL_CALLS`、`STRIPSEARCH_RESEARCH_MODEL_CALLS`、`STRIPSEARCH_RESEARCH_INPUT_TOKENS`、`STRIPSEARCH_RESEARCH_OUTPUT_TOKENS`、`STRIPSEARCH_RESEARCH_ELAPSED_MS`；新作业未配置默认各项 0，表示无固定总量上限；正安全整数表示部署显式选择的限制，取消任意配置天花板。旧账本未保存 limits 时仍冻结历史 12/8/150k/16k/240 秒。限制保存在 checkpoint；重启不按新配置悄悄扩大本次批次。配置上限是服务端保护，非研究质量保证，也不是硬美元账单上限。

历史 v1 回放数据/证据不改写；当前生产行为采用 [v2 合成回放](../evals/research-baseline-v2/README.md)，明确冻结期望变化，未评测真实自动规划质量。无本地供应商凭据时只能验证程序及会话连接器的真实读取，不能宣称生产全链路 live 通过。

原始 corpus 不设固定页面数，保留供应商返回的全部正文、页面和自链。模型每轮只看目录窗口（12 个来源、每来源 20 条链接、30 项未知）与选择的 4000 字符正文窗口；这些窗口可通过本地 catalog / inspect 换页，不消耗工具 HTTP 请求。发送窗口前重新校验当前活跃来源，旧缓存正文不作为输入，撤回材料不能借 inspect 重现。重复工具或同一窗口无进展时停止为 partial:no_new_evidence，避免无限规划扣费；它是无进展判定，不是总轮数限制。

一个平铺批次接受的最多四个 inspect 窗口全部以来源键与偏移持久化，下一轮按活跃、已选来源重新生成原文，不仅传最后一个窗口，也不缓存可复现撤回内容的文本。旧单窗口检查点保持兼容。已选范围规划收到最多四项真实动作结果（新材料、已见窗口、重复动作、读取失败、未发现地址或范围拒绝）；这些是控制器反馈，不是来源证据。范围批次连续两次没有新增材料时停止为 partial:no_new_evidence；第一次保留一次纠正规划与基于现有原文结束的机会。成功读取新原文或新目录/正文窗口会清除连续无进展计数，不缩小配置总额度，也不放宽任何派发或引用门禁。

生产新默认与旧回放分开：[连续平台深读](platform-depth-continuation.md)。目录与正文窗口不代表整个平台、历史、媒体或评论已经完整。供应商补充链接索引每请求 100 条，实际返回及正文内链接全部保留；未证明完整的索引仍是缺口。成功读取的费用说明保存在 notes，不充当 unresolved 研究项。

## 单条引文与整体概括

每条研究陈述目前只绑定一个实际原文摘录。单条文章、索引条目或时间点不能被综合成整个博客、全部作品、职业生涯的核心观点或一贯立场。共享的保守范围守卫同时用于模型核验落库和 canonical 呈现；即使模型返回 supported，命中整体主体与总体性措辞的组合仍拒绝，记录缺口。明确限定于该篇文章的表述不因此拒绝。

逐字陈述只有精确存在于本条绑定 quote 时才能豁免该范围守卫，不能用整页别处文本或规范化相似文本代替；现有原文、作者、身份和所选范围守卫继续适用。被过滤的历史 checkpoint 不改写原始陈述、回执或来源；新生成报告同步过滤 observations、answer 和 coverage，必要时降为 partial。保留逐字来源供查看，不把摘录当独立事实核实。这是有界的语言守卫，不能替代独立语义审查。

结构化结论契约：五个研究维度均保留原证据门槛。第一步后的模型允许一次提交最多 8 条简洁结论，每条必须声明实际回答的 `facet`（五维枚举）；原文引文仍限制为精确连续 3–600 字符。最多四个批量动作与 2500 输出 token 的原预算不变；不能因五维覆盖目标补写结论或把失败读取当反证。缺任何维度仍为 partial。历史缺维度的结论不会由新契约补填。

单条引文核验（`exact_quote/v1`）：新第一步 Fetch 的核验只接收该条实际连续引文及其原文偏移，不再把前后 ±400 字符作为额外陈述依据。作者与时间元数据只用于来源归因/展示，不能补写引文之外的经历、角色、年份或其它文章；多条独立材料拆成独立结论，或选择能完整支持本条的 ≤600 字符连续摘录。确定性年份守卫还会拒绝陈述中引文未出现的 1500–2199 年份，即使模型误报 supported。其它语义仍需模型与独立实际审查，不冒称该守卫能证明全部含义。新检查点记录此核验政策，落库及 canonical 重建使用相同守卫；历史未记录政策的原文、核验及陈述不回写、不改成新政策已核验。

核验政策进入真实模型回执的请求描述与幂等键（`model:<step>:quote_only_v1`），不得用旧 ±400 窗口的已完成回执冒称新政策通过；旧成本仍计入冻结预算，未知/inflight 不重放。实际 `Store.buildCanonicalView`、Person Object、observations、answer 与 coverage 同时使用共享证据守卫；只隐藏被拒陈述并保留可读原始材料与缺口，完成态按证据降为 partial，撤回/范围失效优先级保持。
