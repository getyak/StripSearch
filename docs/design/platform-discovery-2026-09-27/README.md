# 平台发现、身份一次性校正与帖子深度追踪提案

状态：**部分已实施**。`apps/web` 已落地平台发现 / 身份校正 / 帖子追踪模块（共享契约、探测引擎、外部工具报告导入、持久任务与检查点续跑、HTTP API）；离线验证记录见 [REVIEW](REVIEW.md)。**除沿用既有 GitHub 端点验收标签外，其余平台规则与外部报告结果均为 `live_unverified`；本模块未执行新的真实平台复核，不能据此宣称发现准确率。**

2026-09-27。本提案回答：如何用「邮箱查注册网站」「用户名查全平台」两类开源 CLI 的能力，扩展 StripSearch 的资料发现面，同时不破坏身份归属、证据与分析分离的底线。

## 一句话设计

**发现候选账号是一次检索；确认身份是一次显式修订；追踪帖子是只读已确认归属的深度取证。** 三者分别落账，任何一步都能被撤回，任何结果都带着它的收据（谁产出、什么格式、是否被复核）。

## 动机：信息太少，覆盖面太窄

本提案起草时的 Web alpha 以 GitHub 公开资料 + 可选 Exa 为主（当前研究运行范围见[实现说明](../../person-research-release.md)）。当时提出两条待探索的检索轴：

- **邮箱 → 注册过的网站**（[holehe](https://github.com/megadose/holehe) 一类，用“忘记密码”流程探测注册痕迹）；
- **用户名 → 全平台可能账号**（[maigret](https://github.com/soxoj/maigret) / Sherlock 一类，3000+ 站点枚举）。

它们能把研究从“一个主页”扩展到“这个人活动过的地方”，再对每个平台做**帖子级深度追踪**。但它们也是双用途工具：用户名相同不等于同一人，报告自带误报警告，maigret 生态有明确的 stalkerware 争议（见 [REVIEW](REVIEW.md)）。所以接入方式必须是**受约束的探测 + 显式归属**，而不是把 CLI 的输出当结论。

## 本轮交付（已实施，离线验证）

| 能力 | 实现 | 验证 |
|---|---|---|
| 共享契约 `platform-discovery/v1` | `apps/web/src/shared/platform-discovery.ts` | 纯函数测试 |
| 平台注册表（13 规则，含 import-only 平台） | `apps/web/src/server/platforms/registry.ts` | 注册表接口 + 诚实验证标签 |
| 原生 HTTP 探测引擎（状态/标记语义、超时、限体） | `apps/web/src/server/adapters/discovery.ts` | 合成传输层 7 组场景 |
| maigret / holehe 报告导入（输出格式按源码核实） | 共享解析器 + 导入 API | 合成报告解析、字段丢弃断言 |
| 持久任务 + 检查点续跑 + 迟到结果守卫 | `discovery-store.ts` / `discovery-runner.ts` | 重启恢复、取消、幂等 9 组流程测试 |
| 一次性身份校正（允许来源的精确 `rel=me` 自链，其余待人工） | 校正 API + 修订账 | 状态机、整批回滚与撤回级联测试 |
| 帖子深度追踪（JSON 列表 / RSS、分页、摘录+定位） | 帖子抓取器 | 分页、坏载荷降级、归属有效性 |

## 明确不做

- 不做匿名身份揭露、私人位置/行踪追踪、泄露库查询或访问控制绕过（与产品红线一致）。
- 不实现“忘记密码”式邮箱注册探测的原生路径；邮箱轴只接受外部工具报告导入，探测行为的合法性由运行者负责。
- 不抓取帖子正文全文；只留列表页摘录与定位。
- 不宣称任何平台规则已 live 验证；唯一例外是 GitHub 端点语义（沿用既有 GitHub adapter 的验收范围）。
