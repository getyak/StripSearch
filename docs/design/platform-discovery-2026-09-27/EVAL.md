# 评测设计：发现质量、归属精度与成本

状态：设计稿。以下是**要怎么测**，不是已测结果。当前已验证的只有离线测试（187 项）与冻结回放（40 案例，0 网络调用）；平台发现的模型/检索效果**尚未评测**，不得引用为能力。

## 1. 分层测量，各说各话

| 层 | 问题 | 手段 | 不允许的推断 |
|---|---|---|---|
| L0 契约 | 状态语义、解析、状态机是否正确 | 离线单测 + 合成传输层 | 不代表真实平台命中 |
| L1 端点 | 每条注册表规则 live 语义对不对 | 逐规则实测：已知存在/不存在各 1 例，记录状态码与标记 | 不代表发现质量 |
| L2 发现 | 候选账号找得全不准 | 已授权对象上与 maigret/holehe 全量报告对齐 | 不代表身份正确 |
| L3 归属 | 确认的账号是不是这个人 | 人工独立核验（互链/自述/第三方），盲评 | 不代表研究结论质量 |
| L4 追踪 | 帖子/时间线是否支持研究问题 | 案例制深评（对照[评估设计](../../evaluation.md)） | 不代表整体产品收益 |

## 2. L2/L3 实验设计（待执行）

- **对象集**：20 个已获授权对象（本人志愿或公开职业人物），中英各半，资料稀疏/丰富各半；按人物隔离 holdout，调参集不进保留集。
- **基线对照**：① 仅 GitHub+Exa 的现有一行式方案；② 裸 maigret/holehe 报告直出；③ 本方案（发现→一次性校正→追踪）。同输入、同请求预算。
- **标注**：每候选账号两名独立评审标注“是/否/无法判断这个人”，分歧人工裁决；模型不得自评当 gold（沿用[标注工作台](../../annotation-workbench.md)口径）。
- **指标**：
  - 发现 precision/recall（对人工确认的账号全集，含工具并集作上界参照）；
  - 归属错误率（把别人的账号确认成研究对象 = P0 失败，单独计数不平均）；
  - needsReview 负担（每对象待决候选数、人工分钟数）；
  - 追踪有效性（帖子时间线回答了几个既定研究问题，需人工判定）；
  - 成本（请求数、字节、外部工具运行时间；超时记 `outcome_unknown` 不记零）。
- **报告**：保留失败与 partial；按平台/语言切片；报告不确定性（bootstrap 区间）；不删误报案例。

## 3. 判定器校准

- 人工标签先行；自动判定只做初筛，判定结果与人工标签分开保存。
- 归属判定不允许纯用户名相等规则升级为自动通过（与契约一致：`exact_handle` 只是 basis 不是结论）。
- 校准目标：把“漏看反证”的比例压到可报告水平，而不是把通过率调高。

## 4. 复现与许可

- 每次评测冻结：注册表版本、工具版本（maigret/holehe 的 commit 或 PyPI 版）、任务参数、预算、时间窗。
- 公开材料只用合成或明确许可者；真实人物材料留在本地忽略目录（与 [AGENTS](../../../AGENTS.md) 红线一致）。
- 离线检查（`scripts/check_design.py`）永不含网络；live 验证的账单与 ToS 复核单列。
