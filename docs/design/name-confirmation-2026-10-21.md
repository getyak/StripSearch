# 姓名检索：先确认人物，再选择账号范围

日期：2026-10-21。适用于本地 Web alpha 的新姓名检索。

## 流程与边界

1. **人物概览**：有界普通网页检索，加上已观察到的公开非社交介绍页、文章、百科和个人站的最小读取。展示来源支持的候选；同名来源分开，不按姓名或 handle 合并。此阶段不展开社媒账号或历史内容。
2. **人物确认**：用户选择目标，表达研究意图。服务端重新核验来源与版本；这不证明任何账号归属。
3. **账号发现**：根据所选候选的真实来源上下文查找公开账号，回到 GET-210 的账号工作台。
4. **范围确认与 Fetch**：用户另行提交一次原子账号范围选择，冻结范围后才能读取所选账号的历史内容；逐派发、逐摄取范围检查保持有效。

明确的公开账号链接仍是直接账号目标，不是现实身份证明。旧 `v9/v10` 尝试保留策略、回执键、快照和恢复方式。不承诺覆盖全部互联网信息。

## 共享约定与来源

`shared/person-confirmation.ts` 定义 `stripsearch/person-confirmation/v1` 与新策略 `first-step/v11`。共享约定先于服务端投影和前端呈现。

- `read` 表示取得并保留了原文，携带内容哈希；定位到查询姓名时提供确定性的原文摘录与位置。`indexed` 只表示搜索索引线索，不携带原文哈希或原文引文。
- 描述来自来源标题和保留原文的字面摘录，无模型自由生成的传记。同域目录或百科中的不同页面分别保留候选，不按站点账号键合并人物。`/`、`／` 分隔的已输入姓名任一匹配即可，摘录定位实际出现的姓名；不创造别名。原文定位以 JavaScript 字符串偏移为准，规范化匹配映射回原始文本。
- 原文以 URL 与内容哈希区分版本。同一 URL 在新尝试中更新时，确认匹配本次概览引用的真实版本，保留旧回执，不按最早回执替代新版本。
- 概览属于检索材料和研究意图，不直接进入人物事实结论，也不替代既有 Case 事实、身份依据及撤回规则。第三方人物介绍不成为本人账号。

## 服务端权威

`POST /api/runs/:id/first-step/person-confirmation` 只接收 `expectedRunRevision`、`expectedScopeVersion`、`discoveryRevision`、`candidateId` 四个字段。来源、URL、原文和其他附加字段均不接受。`inputRevision` 从持久化概览与当前输入绑定中核验，不由客户端指定。

确认事务核对当前 owner、run/scope/discovery/input 版本、不可变候选及其真实来源依赖；拒绝越权、伪造、过期、取消和缺失或哈希不匹配的来源版本。同键重复请求回放已有结果，不重复派发；补线索产生新输入版本并撤销旧确认。账号选择仍由另一事务授权，不能越过人物确认。

Runner 在构造受检工具面和发现协调器前使用同一个冻结阶段决定。新姓名尝试先 overview，再 accounts；overview 不调用模型，accounts 独立冻结已配置的 Search Agent 策略，重启复用已有冻结策略；旧策略和明确账号输入保持原流程。所选人物的真实来源上下文影响后续账号查询，不能只改变显示标签。

HTTP 402 记录为安全、非瞬时的 `provider_billing` 服务失败，区别于真实零结果、权限、限流、超时、网络与未知结果。失败元数据绑定尝试和回执键；同尝试跨重启不重复调用该供应商，显式新尝试和其他已授权供应商分别处理。未派发路线记为 deferred/skipped，不伪造完成、覆盖或费用；未知费用保持未知。供应商正文、令牌和凭据不进入公开错误信息。

## 页面

候选默认展示一段描述，来源链接、完整摘录、定位和哈希按需展开；索引线索明确标注未读原文，反向线索保留。确认期间锁定选择，输入焦点及中文输入状态保持稳定。确认后进入紧凑账号工作台，人物确认与账号范围确认分别操作。

服务故障显示明确原因和手动重试；空结果提供区分线索入口。新尝试重新绑定版本，不自动重试计费失败，也不把失败解释为人物不存在。

## 验证

合成工具、内存数据库和 HTTP/Runner 回归覆盖派发边界、同名区分、原文与索引、真实来源版本、幂等、旧策略恢复、计费停止及账号范围确认；离线检查不调用产品供应商或抓取 fixture URL。生产构建、真实浏览器、指定账号的实服务验收和模型质量评估分别记录范围与版本，不能互相替代。
