# X 单账号深度研究

本轮目标是让用户明确选择的一个 X 账号完成可恢复的历史读取、必要上下文补读、分析与独立核验，并生成有出处的中文报告。账号可作为独立研究对象；即使已有公开互链，用户仍可在账号菜单明确选择“仅研究这个公开账号”，不必声明“不是此人”或更换人物候选。不据此确认真人身份或合并其它平台。原任务、材料和失败记录保留，真实验收使用新的单账号任务。

## 读取与恢复

历史帖子与账号回复分别沿供应商真实游标连续读取，逐页计量并保存原文、作者、发布时间和实际返回边界。空的过滤结果不表示结束；连续 3 个原始页面完全无记录却仍给新游标时，暂停该历史入口并记录供应商无进展，不能将其标成历史结束。其它入口与已取得材料仍继续处理。重复页、游标循环、限流、未知费用和中断分别保留。默认沿端点可访问范围继续，只有供应商明确结束才标记该端点枚举结束，不能宣称整个平台历史完整。

依据实际原生 ID 补读回复父链、引用原文和讨论页。第三方内容只作为有关系绑定的上下文，不能成为目标本人发言；不得拼接或猜测外部网页地址。评论按既有默认首层一页约定读取，后续游标和未读范围明确保留，不伪装完整讨论树。父链沿已观察到的父帖 ID 继续，重复节点停止；缺失或不可读记录缺口。

每次真实请求使用现有 reserve / settle 账本。已完成动作恢复时复用保存的结果，未知 inflight 不重放；取消、账号范围变化和来源撤回必须及时停止。用户明确重试同一账号与冻结范围时，新任务可复用父任务已完成且来源未撤回、未变更的读取回执，标记复用来源与零新增费用；已结算失败可重新读取，未知未结算动作仍暂停，不能用重试绕过。新字段只影响新单 X 账号路径，旧报告保持可读。独立上下文请求与独立分析批次采用有界并发（当前每类最多 3 个），这不是总读取量或材料抽样上限。每次读取（包括回执复用）在派发前让出一次事件循环，再检查最新权限与取消状态，避免大规模回放阻塞网页与取消请求。相同原生请求不同时派发；首个停止原因出现后不再启动新批次，等待已经发出的请求落定后再形成部分结果，避免收尾后的迟到写入。

## 分析与核验

出处面板面对大量原文时按页浏览，每页最多 100 条，显示实际总数并可前后翻页；引用或搜索选中的来源自动进入所在页。分页只限制同时创建的界面行数，不限制读取、分析、保留或导出的来源。筛选、切换任务和键盘导航须保持正确的范围与焦点。

长任务的授权检查仍在每次派发和入库前查询当前数据库，只读取冻结范围字段，避免反复解析整份正文检查点；这不是授权缓存。单条回执按动作键读取，额度统计只读取计费字段，不改变未知请求、预算预留或撤回的判断。

来源检查在数据库内逐次比对来源是否存在、已排除，以及链接和正文是否与期望材料完全一致，避免每次把全部正文和元数据重新搬入应用内存。只复用期望材料的序列化描述，不复用有效性判断；当前语料每次新增或更新后重建描述，祖先描述固定为本轮读取时的材料。实时来源改动仍使下一次检查停止。

HTTP 截止时间覆盖连接与正文读取；底层读取或取消未响应时，本地等待仍必须按时失败。超时与取消后的迟到结果不得进入语料；超限流的资源清理不能阻塞错误返回。超时回执表示本地执行失败，不代表供应商取消成功或费用已结清，未知费用继续保留；同一任务不得重复发送已有失败回执对应的请求。

同一原生单帖可能被多条回复用作父帖或引用。已排队的同一 detail 请求可合并处理，每组最多 100 条关联：只读取一次，逐一保留各自 root 与关系，父链只沿需要父链的关联继续；完成后统一保存该组检查点。分组不改变最多 3 个不同原生请求在途、全部已发请求收尾后再停止，以及完整来源核对的要求。

上下文供应商明确返回计费或额度拒绝时，停止后续补读批次，等待已发请求收尾，并保留未读关联；不能继续发送注定失败的请求，也不能把这些关联标为已读。已有材料仍进入分析、独立核验与中文综合，结果标为部分覆盖并说明供应商拒绝原因。同一检查点恢复时保留该读取边界；新增费用或重读失败请求须走明确的新重试范围。

完整已存语料分批分析，不以最近一页代表全部。本人正文基础批只处理一次；上下文批只附带通过原生父帖、引用与 root 关系关联的正文窗口，并只形成实际引用上下文材料的新发现，不把无关的整组本人帖子反复放进每个评论批次。未关联上下文仍单独处理一次，所有正文窗口保留。分析计划版本进入检查点签名，旧分批结果不能混入新计划。中文报告按主题与观点、时间变化、具体作品、互动与争议、商业合作及局限组织。只有实际材料支持的章节才形成结论，不补造经历或人格判断。当前只读取正文；图片、音视频与链接页面未读。不能由配图链接、见面文案或表情推断合照、画面等媒体事实；涉及这类观察时，至少须有去除 URL 后仍明确描述媒体的所引正文，并继续独立核验其具体含义。

每条陈述可绑定多个来源的精确原文与内容 hash，分析与核验分别调用模型；逐条检查引文存在、作者角色、陈述含义和中文表达。未知、广告、自述、推断和第三方意见分别表达。核验响应漏条目、标识错误或重复时，携带精确条目列表与结构错误最多修复两次；仍逐字核对标识、完整分区与原文，不模糊匹配或接受不完整批次，超限保留部分结果。最终综合仍只使用可核验材料并再核验，不把上一轮模型摘要当原始证据。来源撤回或范围失效后，依赖结论变为待复核。

解释回复时，提问者说了什么也属于待核验事实。陈述包含读者提问、第三方观点或反驳内容时，必须引用实际对应上下文，不能只引用本人回复再补写问题；核验需逐句检查这些归属和限定。英文格式的原生发布时间先解析为日期，再用于年份与先后关系判断。规则升级后重新分析旧批次，旧核验标签不能替代新检查。

模型失败保留本地错误码、响应状态与哈希、流是否完整、已知用量等诊断元数据，不保留任意异常正文或泄露凭据。只有完整成功响应中的明确结构化协议缺陷可以携带相同原文与格式要求，最多追加两次独立计量的修复；旧失败空回执、取消、范围失效、未知传输或未完整结束的响应不能自动重发。修复耗尽只留下该批分析缺口，继续其它独立批次；失败批不算完成，最终结果保留部分覆盖。

核验和专题综合使用现有模型的推理模式，每次核验最多四条陈述；原文批次生成保留原有模式。原生时间先解析为 UTC，时间间隔由程序计算供核验，不能由模型随意估算。核验逐项检查本人自述与已证实事实、观点的语义强度、比较对象及是否真的存在冲突；第三方改述的强命题不能反过来归给本人。核验规则升级后重新核验所有候选，已有生成回执可以按原请求复用，旧核验结论不能复用。推理内容不进入产品展示，实际输出用量与费用按回执记录。配置依据：[DeepSeek 推理与强度控制](https://api-docs.deepseek.com/guides/thinking_mode/)及[Anthropic 格式支持](https://api-docs.deepseek.com/guides/anthropic_api/)。

实际接口拒绝推理模式与指定工具的组合，因此推理核验采用 `tool_choice:auto`，只开放同一个结构化提交工具，仍只允许一次模型请求且必须取得有效结构化结果；没有工具结果时按已有已知协议缺陷的有限修复规则处理。非推理生成保留指定工具。两种参数计划使用不同动作键，历史拒绝回执原样保留，不能用修正后的请求伪装成旧请求重放成功。

全文成稿分开于材料阅读。全部既定原文窗口仍逐一处理，生成的候选只作为内部研究索引，未经独立核验不能展示为结论；已通过核验的旧阶段发现和所有已完成阅读、回执继续保留。全局整理先从完整索引归并主题、重复和主线，再按主题回到真正原文写作，并逐条独立核验最终陈述。不能把每个小批次的局部综合直接铺成整篇报告，也不能用摘要或旧核验标签代替最终证据。主题规划、成稿及完成标记独立记录，旧局部综合完成不代表全文成稿完成。主报告只展示通过最终原文核验的内容，原始材料与内部候选保留可追溯；没有证据的维度不凑数，不以任意全账号八条上限截断研究。

分段主题归并至少减半收敛，最多十二轮；达到本地规划上限时保留索引与成稿缺口，不当作供应商数据结束或格式故障。规划各分段最多三个并行请求，按分段顺序保存结果；恢复时通过确定性请求键复用已付回执。

独立账号报告具有账号主体，不进入 Person Object 的人物断言。界面、JSON、Markdown、HTML/PDF 共用 canonical 数据；账号覆盖与人物五类维度分开。报告正文包含实际页数、保留账号与上下文记录数、日期范围、端点边界和未读媒体说明；界面及导出共用这一段边界信息。只有形成有效发现后才附上，覆盖统计不能单独伪装为分析。原文不是最终分析。

## 验收

离线回归覆盖分页恢复、循环、空页、外部作者隔离、上下文关系、取消/撤回、引文和核验拒绝、独立账号中文报告与导出。离线检查不联网。

真实验收针对用户指定的 X 账号，使用既有认证工作区与供应商配置。记录真实分页、上下文、模型/费用回执和中文报告；完整原始响应只在授权私有目录保存。至少检查跨页材料、实际父链或引用补读、经独立核验的中文专题陈述、可点击来源和覆盖边界。平台访问限制仍可能使覆盖 partial，不能用“部分完成”代替有用分析。

官方请求契约：[历史帖子](https://docs.tikhub.io/191321711e0)、[账号回复](https://docs.tikhub.io/215701675e0)、[单帖](https://docs.tikhub.io/191321709e0)、[评论](https://docs.tikhub.io/215701674e0)。官方公开 schema 未定义响应 data 内容，解析器须绑定实际探针观察到的结构，未知形状明确拒绝。
