# Search / Fetch 证据阅读

GET-288 在既有纸面阅读基线上细化工作台。`PRODUCT.md` 是 Impeccable init 的产品记录；事实来自工单与已有契约，未新增产品承诺。界面采用 Read / Operate 模式。

## 共享呈现契约

- Search 保留 canonical 结论和稳定引用锚点；类型与出处单独成行，正文集中呈现判断。缺少引用明确提示尚无可核对出处，不生成来源。
- 出处按标题、返回原句、原文摘录、原始链接、身份与限制、修订动作组织。平台识别、获取时间与完整 URL 收在默认关闭的“来源记录”；安全链接和排除/恢复操作保持直接可达。记录展开状态只属于同一报告的同一来源。
- Fetch 按目标简名、研究问题、真实状态、暂停/恢复/停止、待核原文、阅读缺口、访问限制、运行记录排序。请求计数和快照处理默认折叠。待核证据不升级为结论。
- Fetch 原文保留作者、时间、证据角色及撤回状态；来源 URL 复用保守 HTTP(S) 安全投影，缺失或不安全地址只显示文本。原文始终以纯文本渲染。
- 零证据说明尚无待核原文；零显式缺口不表示全部历史已读。未知请求选择与恢复动作保持同组、可见且依原有 revision 绑定。
- 不新增网络依赖、远程字体、图像或装饰动效；窄屏维持同一 DOM 阅读顺序。

## Impeccable 工作流

按官方项目级 Cursor 安装，使用 `init`、`clarify`、`distill`、`layout`、`polish` 的当前 playbook。clarify 处理问题/状态与错误用语；distill 合并重复元数据；layout 调整原文优先顺序与阅读节奏；polish 核对窄屏、深色、焦点和恢复状态。独立布局评估与机械扫描分别完成，再合并判断。

具体检测、离线/浏览器验证、独立 review、CI、发布读回按实际证据记录，不能由本文的设计规则推定通过。


## 安装与检测范围

项目执行 `npx impeccable install --providers=cursor --scope=project`，安装的技能版本为 4.8.0，引擎为 0.1.18。上游为 [pbakaus/impeccable](https://github.com/pbakaus/impeccable)，Apache-2.0；生成的 Cursor 技能、代理和 hook 配置随项目保存。没有新增模型调用或运行时产品依赖。

检测结合结果模块源码与合成浏览器中的实际 Search/Fetch 页面。根目录 `DESIGN.md` 明确登记既有纸面配色，避免将产品已确认的色板误判为无依据的默认配色；没有整体忽略任何规则；该配色启发式没有可提取的颜色值，因此仅对 Fetch 路由 `*#/fetch` 豁免 cream-palette；对比、布局及其他规则照常检查。完整静态 HTML 会把隐藏首页与动态工作台一并分析，逻辑 padding、变量间距和状态选择器的结果须和实际渲染核对，不把静态结果当成可访问性证明。


## 研究工具对照

[Zotero 官方阅读器说明](https://www.zotero.org/support/pdf_reader)把原文、批注与引用定位连接起来。本单据此采用的设计判断是：判断旁保留短引用，材料在独立阅读区展开，辅助记录按需查看。这里只对照交互原则，没有运行竞品测试，也没有宣称阅读速度或用户偏好优于 Zotero。

| 阅读动作 | 改前 | 本次呈现 |
| --- | --- | --- |
| 核对判断 | 类型、正文与引用混在同一段 | 判断为正文；类型和引用就近另行，稳定锚点不变 |
