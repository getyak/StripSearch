# 评估设计

新增首轮细化：[人物理解任务集 v0.1](person-understanding-pilot.md)。它规定 20 道真实人物任务的设计、证据与裁判协议；目前未运行、未人工裁决，真实名单仅保存在本地私有研究目录，不计入下列已存在数据集数量。

好的 evaluation 能帮助决定下一步改什么：减少了哪类错误，牺牲了多少覆盖，增加了多少核查时间或成本。篇幅、链接数、文风和模型自评都不能替代这个判断。

**2026-09-23 方法补充：** [综合人物研究及评估](person-intent-evaluation.md) 以“深度调研某个人”为默认主任务，共同检查人物信息覆盖，并根据公开表达、互动和作品特点设置人物专属观察点。具体用途与多轮修订作为补充。工作台 10 个合成练习保留为教学，不承担产品效果证明；真实研究探索与现有离线回放分轨，尚无模型胜率或人工 gold。

**当前数据：** 原有 12 个设计案例保留；新增 [40 个运行时回放案例](../evals/runtime-v1/README.md)、[11 个控制器回放案例](../evals/research-baseline-v1/README.md)、[8 个行为判断案例](../evals/behavior-v1/README.md)与 [24 个 FRAMES 问题](../evals/external/frames-v1/README.md)。程序回放、语义评审、真实 provider 验收分开记账；Runtime v1 是 provider 契约回放，Research baseline v1 是控制器回放，两者都不冒充研究质量。Behavior 与 FRAMES 尚未产生候选答案，全部本地期望未经人工裁决，不作为 gold。

## 先过硬门，再比较收益

严重错人归属、伪造证据、禁止数据泄露与越权操作任一发生，该任务失败；不能用可读性高分抵消。输出引用外键、样例一致性、状态与工具契约使用确定性断言检查。

其余质量同时报告，避免“什么都不知道”刷高准确率：

| 指标 | 分子 / 分母或观察量 | 必须搭配 |
|---|---|---|
| 身份绑定 precision | 正确接受的归属 / 全部接受的归属 | 错误拆分、歧义识别、可解决项覆盖 |
| 原子事实 precision | 正确人物、时间与证据支持的断言 / 全部事实断言 | 未引用/无法核验也进分母；重复断言去重 |
| citation entailment | 实际支持的 claim–evidence 对 / 全部支持引用对 | 反证边分开；链接可打开不等于内容支持 |
| citation completeness | 有有效引用支持的事实断言 / 全部事实断言 | 自述归属是否被升级为客观事实 |
| 关键问题覆盖 | 正确覆盖的预先定义 rubric 权重 / 全部适用权重 | unanswered、超时、失败都计入 |
| conflict recall | 明确呈现的必要冲突 / 全部 gold 冲突 | 有效时间不同未必冲突 |
| 恰当保留未知 | 不可回答项正确 abstain 的比例 | 可回答项的回答率，不能只报一个总分 |
| 任务成功率 | 通过硬约束与任务 rubric 的任务 / 全部启动任务 | 按同名、语言、稀疏性与任务类型切片 |
| 用户核查成本 | 同题配对核验用时与错误数 | 系统名隐藏、材料顺序随机 |
| 运行成本 | 请求数、费用、首个有证据结果时间、P50/P95 延迟 | 失败不丢弃；未知费用不填 0 |

precision 分母为 0 记 N/A，同时显示覆盖。来源独立性按原始来源簇计算，跨 provider 读到同一篇文章不增加证据数。分析假设评价其证据归属、反证、因果克制与可修订性，不设一个“真实人格”标准答案。

首轮先报告计数、区间与错误类别。98% 准确率之类阈值只有在任务损失、样本量和人工标注成本明确后才冻结；不把设计目标伪装成行业标准。零个观察到的严重错误不证明总体风险为零。

## 三层试验，不能混为一个分数

1. **材料/契约回放：** 当前种子、格式引用、分页、取消、重试、身份撤销。无网络回放先验证可审计闭环。
2. **Provider 契约试验：** 拟用 30 个已知公开页面，按可读性、分页、原链接保真、失败恢复、成本分层；检验“能否可靠取回”，不是人物研究准确率。
3. **端到端研究：** 拟用 60 个任务，比较身份、证据、覆盖、核查时间和成本。冻结语料与实时网页分轨。

第 2 层已有独立 GitHub 冒烟（2 请求、9 来源），尚未完成 30 页面试验；第 3 层未运行。只给出文档和 source 文本的 frozen 测试测不到搜索规划；要测检索，必须提供固定的查询 → 候选环境或真实可记录网络环境。

## 数据集与标注

现有 [cases.jsonl](../evals/cases.jsonl) 与 [fixtures.json](../evals/fixtures.json) 为原创合成、discovery、unreviewed。所有 `example.org` URL 禁止真实抓取。种子期望是待评审 specification，不是已确认 gold。

扩展计划为 36 个真实任务（12 名公开人物 × 3）+ 24 个合成任务；真实材料仅限公开职业活动或有明确授权与许可的内容。

| split | 真实任务 / 人物 | 合成任务 | 总数 |
|---|---|---|---|
| discovery | 24 / 8 | 12（现有种子） | 36 |
| regression | 6 / 2 | 6（新实体组） | 12 |
| holdout | 6 / 2 | 6（新实体组） | 12 |

同一人物、别名、来源族和问题变体必须同 split。当前种子共享一个实体族，只能留 discovery。公开整个 holdout 后，它不再是未来调参的盲测集；下一版本另建冻结集。许可不允许重发正文时仅发布 URL、允许的短摘录/定位、hash 与采集说明。

两名独立标注者确定身份、必要事实、可接受未知、禁止推断、时间与引用，再裁决分歧。记录一致性与裁决原因。生成结果至少抽检 20% 任务且不少于 10 个；所有严重错误候选、judge 分歧和无法核验项人工复核。没有第二位评审时诚实标为单人探索，不改写成双盲 gold。

人工标签入口见[标注工作台](annotation-workbench.md)：`/#/review` 提供持久化的两阶段评审（证据与论断正确性、盲选偏好）与版本化导出。它记录 `human_single_review` 的探索性标签，尚未产生已接受 gold，也不代表任何评测已经通过。

LLM judge 只接收限定断言与证据，返回标签和定位。来源不可读记 unjudgeable 并单独报告；保守 precision 不把它计入支持分子。模型风格不能替代证据。

## 比较与消融

- B0：同一 LLM + 同一检索预算的普通研究 prompt。
- B1：维护中的 GPT Researcher 或 Local Deep Research 固定一个版本。
- B2：Exa 的结构化研究能力，作为端到端方案；若模型/来源不一致，不声称因果归因。
- Candidate：加入身份归属、来源去重、反证和核验的 StripSearch。

受控消融一次去掉一个模块，保持模型、数据、预算一致。每方案建议至少 3 次运行，冷/热缓存分开；人物内重复不是独立样本。按任务 macro average，配对差异按人物组 bootstrap，比例报计数和区间。小样本只能形成探索性判断。

8 个行为挑战已具备原创短材料与 rubric，见 [Behavior v1](../evals/behavior-v1/README.md)：团队成果误归属、说与做不一致、选择性评论、时间先后误作因果、声称付出却无证据、反例更新判断、晚年自述替代当时记录、资料稀疏却强行推人格。它们单独版本化，不混入现有 12 案例，尚未跑 Agent 或做人工裁决。

## 产品试验

邀请 5 位研究者，各用基线与 StripSearch 做 2 个匹配任务。记录核查时间、错误、需要继续追问的问题与主动复用。探索目标可设为 3 人愿意再次使用、核查中位时间下降约 30% 且覆盖不降低；这是待验证目标，不是发布结果或统计保证。

参考：[FActScore](https://aclanthology.org/2023.emnlp-main.741/)的原子事实思路；[DeepResearchBench](https://github.com/Ayanami0730/deep_research_bench)的研究质量评估；[PeopleSearchBench](https://github.com/LessieAI/people-search-bench)的人物查找约束。最后一个主要评“找到符合条件的人”，不能直接替代单个人物深度研究评估，也应注意作者与被评产品的关系。
